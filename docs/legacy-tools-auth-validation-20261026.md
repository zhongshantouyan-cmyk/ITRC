# 舊工具站登入與儲存修正驗證

## 可部署範圍

`legacy-tools/` 為完整靜態站，共 14 個檔案。講師池排程、公關贊助、證書產生器已載入 Firebase Auth SDK、共用登入程式及新的 `itrc-cloud.js`。既有 Google 登入與 `roles` 角色查核完成後，才訂閱各頁原有資料路徑；不新增資料表或自動移轉業務資料。

- 未登入、帳號未授權、登入元件缺漏、讀取遭拒：不讀取共用業務資料，不改用本機儲存冒充成功。
- 須等連線及每個初始資料快照載入，才能發出儲存。
- 儲存成功訊息須等待 Firebase Promise 成功；拒絕與斷線顯示尚未儲存，後續資料快照不會把失敗提示改成成功。
- 登出後移除訂閱；過期的角色查詢和儲存回應不會重新恢復已登出的身分或顯示成功。
- 測試角色切換只允許 localhost、127.0.0.1、IPv6 loopback 及 file://；正式網站即使 SDK 載入失敗亦不降級為測試身分。
- 公關及證書的共用業務資料不在登入前讀取舊本機快取；損壞的個人偏好快取不會阻止登入初始化。
- 歷史姓名／私人信箱／財務 seed 和匿名試算表 CSV 匯入仍已移除，空的資料庫不會自動回灌。

資料路徑保持為 `activities/state`、`sponsors/records`、`sponsors/pipeline`、`sponsors/cands`、`certs/positions`、`certs/template`。

全站掃描未發現非社團且非範例信箱、匿名 `gviz`／`output=csv` 來源、非空幹部 seed 或非空歷史帳務 seed。這是指定模式的靜態檢查，不代表所有自由文字均已完成資料分類。

## 部署後仍需驗收

此報告不宣稱正式部署或真實 Firebase 儲存已驗收。部署後應以現有社團 Google 帳號確認登入、角色讀取與三頁現有資料可讀。業務資料仍採整份物件／陣列儲存；多人同時編輯的衝突控制與財務逐筆授權不在此修正範圍。

歷史 Vercel 部署中的舊原始碼需要另行限制存取或依核准程序清理；更新正式網域不會移除舊部署。

`prepare-legacy-tools-hardening.py` 保留為先前來源去識別化的復原腳本；新增登入修正以本版本的靜態檔為準，該腳本不是完整網站建置器。
